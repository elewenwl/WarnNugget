## Что изменено по каждому пункту

| № аудита | Реализация |
| --- | --- |
| 1 | Инъектор принимает Path без предварительной загрузки всего пакета. Копирование, SHA-1 и сравнение выполняются блоками до 1 МиБ; замена файла атомарная, неизменившийся payload сохраняет inode/hardlink. |
| 2 | Перечисление metadata и передача файлов AFC выполняются максимум четырьмя задачами. Общий сервис используется параллельно только при наличии демультиплексирования ответов в установленном клиенте; старые клиенты остаются последовательными. |
| 3 | Чтение/запись блоков, открытие/закрытие локальных файлов, формирование inventory и маркера вынесены из event loop. При отмене ожидается завершение активного дискового вызова, затем освобождаются ресурсы. |
| 4 | Один stat файла и одна проверка каждого общего каталога в пределах проверки; parsed marker возвращается вместе с результатом. Повторный немедленный gate использует уже полученный результат, диагностические логи не запускают полный обход. Основные тяжёлые проверки исполняются в worker. |
| 5 | Генерация video-loop, ZIP и очистка выполняются file-worker; GUI обслуживает события. Открытие папки после экспорта не ждёт завершения внешнего процесса. |
| 6 | ZIP скачивается сразу во временный файл. Распаковка/импорт выполняются worker; включение tweak и обновление GUI остаются в GUI-потоке. |
| 7 | Tendie парсится в фоне. Assets индексируются по имени и читаются по требованию из одного лениво открытого ZIP; общий кэш исходных байтов ограничен 8 МиБ. Результаты не применяются к уничтоженному или закрытому превью. |
| 8 | Удалены PNG encode/decode и тождественный RGB→HSL→RGB проход. Сохранена прежняя preview-аппроксимация: исходный straight RGB с непрозрачным alpha; источник не изменяется. |
| 9 | Индекс ID слоёв вместо рекурсивного поиска на каждый override. Renderer переиспользует рабочее дерево перехода; смена пары состояний создаёт новое дерево. Исходный документ не изменяется. |
| 10 | Prune использует один inventory для наличия payloads, удаления orphan-файлов и учёта опустевших каталогов. После инъекции выполняется отдельная свежая проверка. |
| 11 | При предстоящей инъекции max inode вычисляется в SQL-сеансе prune только по оставшимся rows и передаётся инжектору. Сам необходимый полный разбор этих blobs остаётся линейным; standalone injection сохраняет собственную проверку. Recovery без инъекции не оплачивает этот проход. |
| 12 | Metadata копируются независимым clone/reflink, если FS поддерживает его; иначе обычной копией. Payloads сохраняют hardlink. Возврат pristine master использует смену поколений с rollback и фоновой очисткой retired-дерева; snapshot восстанавливается и после прерывания между rename. |
| 13 | Disposable recovery copy создаётся на томе исходного backup. Ошибка её создания очищает частично созданное дерево; после успешного recovery scratch удаляется в фоне (на сбое сохраняется для диагностики). Перенос backup на внешний диск больше не вызывает полное копирование payloads в системный temp. |
| 14 | Sparse backup копирует и хэширует path-backed файлы потоком. Convenience API `read_contents` сохранён, основной writer его не использует. Подпись last-apply также хэшируется потоком. |
| 15 | Materialise PosterBoard итерирует только regular-file SQL rows и использует потоковое/системное копирование. SQLite-соединение гарантированно закрывается. |
| 16 | Штатный Phase 5 выбирает актуальные entries из проверенного marker. Исторические файлы остаются на компьютере; ручной recovery по умолчанию по-прежнему отправляет весь доступный inventory. При утрате полноты обычный restore спасает оставшееся, но сообщает ошибку вместо успеха. |
| 17 | Live Photo конвертируется сразу в выходной MOV; AAR получает путь и копирует видео блоками, проверяя длину. Полный MOV не удерживается в bytes. |
| 18 | Сравнение locked/home выполняется на миниатюре с длинной стороной до 256 px; результат кэшируется для документа. Это проверка видимого отличия превью, а не сравнение каждого исходного пикселя. |
| 19 | Статические отфильтрованные offscreen-слои кэшируются с лимитами 16 МиБ / 128 записей. Анимированные поддеревья и переходы исключены из этого кэша. Удалены лишние `arr.copy()` перед немодифицирующими операциями Pillow; учтён stride QImage. |
| 20 | Поиск приложений имеет debounce, скрывает/показывает существующие items и сохраняет декодированные icons. Повторного создания items и PNG decode на каждый символ нет. |
| 21 | Полученная иконка находит app/item через словари по bundle_id. |
| 22 | Иконки устройства кэшируются по устройству/bundle/version с TTL 24 часа. Пропуски загружаются через максимум два независимых SpringBoard-сервиса; отказ дополнительного сервиса оставляет последовательный режим. Недоступность кэша не препятствует загрузке. |
| 23 | Каталог иконок материализует только окно видимых карточек с небольшим запасом. Превью вне окна отменяются, очередь — deque; QNetworkDiskCache ограничен 64 МиБ. |
| 24 | Темы иконок хранятся в OrderedDict по bundle_id. Добавление, замена и удаление не сканируют весь список; порядок замены сохранён. `themes` возвращает упорядоченный snapshot, присваивание последовательности заменяет коллекцию. |
| 25 | Metadata пресетов кэшируются по файловому fingerprint. Новые/импортированные JSON пишут metadata первым ключом: её можно прочитать из небольшого заголовка без разбора tweak payload. Старые форматы читаются через полный fallback; внешние изменения инвалидируют кэш. |
| 26 | Рестартуемый debounce autosave на 500 мс; counts объединяются в следующий цикл GUI. Worker получает независимый snapshot, записи одного окна не перекрываются. Выход дожидается записи и сохраняет последнюю конфигурацию; отключение autosave может отменить staged commit. JSON заменяется атомарно. |
| 27 | Неизменившийся log tail не перерисовывается. Новые строки добавляются инкрементально, старый текст хранится для сравнения без `toPlainText`; изменение фильтра/ротация/усечение сохраняют полный rebuild. |
| 28 | ZIP names индексируются один раз; точные имена и wildcard-prefix используют bisect по нормализованному индексу. Сохраняется исходный порядок entries и платформенное поведение fnmatch; пересекающиеся patterns не извлекают файл повторно. |
| 29 | Независимые устройства проверяются конкурентно, максимум три, с бюджетом 15 секунд на устройство. Выходной порядок и выбранный UDID сохраняются; таймаут одного probe не удаляет найденные исправные устройства. |
| 30 | Успешный verdict integrity_check переиспользуется только при неизменном fingerprint main/WAL/SHM. Результаты ограничены 32 snapshots; изменение файла/журнала, новая копия и другой strict-mode требуют новой проверки. Ошибки не кэшируются. |

## Существенные ограничения

- USB-пропускная способность и выигрыш от AFC concurrency не измерялись с
  телефоном. Устройство может последовательно обслуживать команды даже при
  нескольких запросах в полёте.
- Полноценное перечисление дерева, проверка всех payloads, создание hardlinks
  и окончательное удаление retired-дерева остаются `O(N)`. Эти операции нужны
  для сохранности данных или зависят от возможностей FS; фоновые стадии не
  означают отсутствия дисковой работы.
- Атомарная замена требует свободного места для одного нового payload до
  удаления предыдущей версии. Одновременной загрузки всего пакета в RAM нет.
- Max-inode scan продолжает разбирать оставшиеся plist blobs. От него нельзя
  безопасно отказаться, назначив неподтверждённый диапазон inode.
- Старые JSON пресетов без metadata-заголовка впервые читаются полностью.
  Изменённая SQLite-база всегда проверяется заново.
- Статические preview-кэши относятся к неизменяемому загруженному документу;
  при замене документа/состояния renderer пересоздаёт соответствующие структуры.
- Небольшие отличия, исчезающие при уменьшении home-state до 256 px, не включат
  отдельное home-превью. Сами файлы обоев на устройстве это не изменяет.
